YRobot Architecture

Full-duplex MiniCPM-o 4.5 conversation for Reachy Mini Wireless — a 7-thread conversation loop

Seven threads, no shared mutable state

  • • main loop — mic → VAD → barge-in → gate → queue
  • • yrobot-uplink — queue + latest JPEG → websocket
  • • yrobot-camera — encode, latest-only frame slot
  • • yrobot-recv — deltas → gate → speaker / captions
  • • yrobot-speaker — paced, interruptible playback
  • • yrobot-motion — 50 Hz choreographer, owns pose
  • • yrobot-doa — 12 Hz sound compass → gaze

Barge-in — client-owned & destructive

  • • 200 ms candidate correlated vs exact recent playout
  • • echo-explained voice ignored; near-end must persist 500 ms
  • • commit bumps the epoch and calls clear_player()
  • • every unit carries force_listen until its input_id replies listen
  • • 450 ms of user quiet then admits the new answer
  • • response_id is deliberately not a turn boundary

Gateway protocol & context budget

  • • connect ?mode=audio|video, wait queue_done
  • • session.init starts "You are a helpful assistant."
  • • stream exactly 16,000 float32 samples (1 s) per unit
  • • deltas listen | text | audio are independent streams
  • • vision ~64 kv tok/frame: 1 fps active, 0.2 fps idle
  • • rotate sessions at a quiet boundary past time / kv budget
